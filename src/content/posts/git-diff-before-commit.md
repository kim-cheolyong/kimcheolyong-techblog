파일을 여러 개 수정했다면 커밋하기 전에 어떤 변경이 이미 스테이징됐는지 확인하는 편이 좋습니다. `git status`는 파일 단위로 상태를 보여주고, `git diff`는 줄 단위로 바뀐 내용을 보여줍니다.

## 작업 트리와 스테이징 영역의 차이

인수 없이 실행하면 아직 스테이징하지 않은 변경을 볼 수 있습니다. 파일명을 붙이면 살펴보고 싶은 파일로 범위를 좁힐 수 있습니다.

```bash
git diff
git diff -- src/config.ts
```

새로 만든 미추적 파일은 기본 `git diff`에 나오지 않습니다. `git status --short`로 새 파일까지 확인합니다.

## 다음 커밋에 들어갈 변경

`--staged`를 붙이면 마지막 커밋과 스테이징 영역을 비교합니다. 결과에 나온 변경이 다음 커밋에 들어갑니다.

```bash
git diff --staged
```

## 파일의 일부만 스테이징하기

하나의 파일에 서로 다른 작업이 섞였다면 `git add -p`로 변경 덩어리를 하나씩 선택할 수 있습니다. 선택을 마치고 `git diff --staged`를 다시 실행하면 이번 커밋의 범위를 검토할 수 있습니다.

```bash
git add -p -- src/config.ts
git diff --staged
```
